# 鲸鱼娘 · 点歌真唱（SVC 翻唱）接入说明

> 2026-10-18 接入。解决的问题：群友 @她 点一首具体的歌，她用**自己（鲸鱼娘）的音色**
> 把这首歌**唱出来**，而不是回原唱、也不是念歌词。
>
> 改造前的三条后端是「ACE-Step 端到端出歌 / 内置曲调 SVS / TTS 抬调朗读」，
> 它们都唱不了「指定的某首流行歌」。这次补的是第四条：**歌声转换（SVC）翻唱**。

---

## 一、群里怎么用

| 你说 | 她做什么 | 多久 |
|---|---|---|
| `@鲸鱼娘 唱首晴天` | 唱一段（默认，取副歌 45 秒） | 首次约 1—3 分钟，之后秒回 |
| `@鲸鱼娘 唱一段 孤勇者` | 同上，明确要一段 | 同上 |
| `@鲸鱼娘 整首 后来` / `全唱` / `唱完` | 唱完整首 | 首次约 3—4 分钟 |
| `@鲸鱼娘 点歌 洛阳纸` | 默认一段 | 同上 |
| `@鲸鱼娘 唱《爱如潮水》` | 曲库里没有 → 回「没学会，发歌单看看」 | 立即 |
| `@鲸鱼娘 唱个歌` / `随便唱一首` | **不接管**，仍走原来的随机点歌路径 | — |
| `@鲸鱼娘 别唱了` | **不接管**，不会被当成歌名 | — |

要点：

* **一段走语音条，整首走文件。** 微信语音条硬上限 58 秒，所以 45 秒的副歌能直接
  点开听；整首（3—5 分钟）会自动打包成 mp3 文件发出来。
* **同一首歌只跑一次。** 缓存键 = 歌名 + 长度模式 + 音色版本，之后有人再点就秒回。
* **排队是串行的。** 8 GB 显存一次只跑一个 SVC，第二个及以后会被告知「约 N 分钟」。
  队列上限 8，超了直接拒（不会无限堆）。

## 二、它怎么工作

```
群消息 "@鲸鱼娘 唱一段 晴天"
   │
   ├─ CoverService.resolve()            ← 解析歌名 + 长度模式，查曲库
   │     · 命中 → CoverRequest(song=晴天, mode=segment)
   │     · 没命中 → 回「曲库没有」，不往下走
   │     · 不是点歌 → 返回 None，消息照常走原路径（AI / 老点歌 / 寒暄）
   │
   ├─ 先回一句文字（缓存命中就说「现成的」，否则报预计等待）
   │
   └─ CoverService.render()
         └─ 子进程跑 cover.py（用 soulxsinger 环境的 python）：
              取音轨 → demucs 分轨 → 截副歌（能量最高段）→ RMVPE 提 F0
              → SVC 换音色（自动算移调量，目标人声 ~260 Hz）
              → 伴奏同步移调 → 高通 + 短混响 + 混音 → mp3
         └─ 产物落到 data/song_cache/cover/zh11/鲸鱼娘-歌名(歌手)-一段.mp3
            （文件名就是群里看到的名字），下次直接命中
```

发送沿用原来的 `_send_song_audio`：`send_audio(prefer_voice=True)` →
微信语音条（虚拟声卡 + UI 点击）→ 失败或超长自动回退 `send_file`。

## 四、配置（`config.yaml` → `voice.songs.cover`）

```yaml
cover:
  enabled: true              # 总开关，改 false 立刻回到改造前
  default_mode: segment      # segment=一段（默认）/ full=整首
  segment_seconds: 45        # 一段多长
  cache_dir: ./data/song_cache/cover
  work_dir: D:\鲸鱼娘SVC翻唱
  script: D:\...\cover.py
  python_exe: D:\miniconda\envs\soulxsinger\python.exe
  prompt: D:\...\_voices\ZH_SPK_11_0.wav    # 音色参考
  voice_version: zh11        # 换音色时改这个，缓存自动失效
  library_dirs:
    - C:\Users\你的用户名\Music
    - D:\鲸鱼娘\曲库
  timeout: 900
  max_queue: 8
```

改配置后重启 bot 生效（`voice` 有 Web 热更新通道，但 `cover` 段目前只在启动时读取）。

## 六、已知限制（别当成 bug）

1. **曲库只有 66 首。** 群友点周杰伦、陈奕迅的大部分歌会「没学会」。补齐有两条路：
   往 `library_dirs` 里丢文件（最快），或者接一个「按歌名搜 B 站 → 取音频 → 再翻唱」
   的兜底（`cover.py` 本身已经支持 BV 号，缺的只是搜索那一步）。
2. **首次点每首歌要等 50—190 秒。** 分轨（demucs）约 30—40 秒 + SVC 约 20—150 秒。
   同一首歌第二次是秒回。想预热就提前跑一遍。
3. **一段和整首的调不一样。** 移调量按「这次要唱的那段人声」的中位音高反推，
   所以副歌高的歌，一段会被少升一点。各自都在 260 Hz 附近，但同一首歌两种模式
   听起来会有半个到一个半音的差别。要统一就把 `segment` 的移调改成按全曲算。
4. **音色是借来的。** 参考音频是 SoulX-Singer 公开测评集里的 5.9 秒女声
   （ZH_SPK_11_0，236 Hz），不是鲸鱼娘本人的声音，也和她说话用的 edge-tts 晓晓不同。
   技术链路成立，但「鲸鱼娘到底什么声音」这件事仍然要人来拍板。
5. **响度没达到 −14 LUFS**（实测 −15.4 ~ −18.4）。`cover.py` 已经支持
   `--lufs -14`，但默认关着——因为改响度会改变现在这套你认可的听感。
6. **语音条是 UI 自动化。** 走虚拟声卡 + 点击微信按钮，前置条件（VB-CABLE、
   微信窗口）任一不满足就会自动回退成发文件，不会失败。

### 9.3 试运行暴露并修掉的两个真 bug（影响所有语音条）

**bug 1：录音态判定阈值过期。** `voice_sender.REC_STATE_DIFF` 写的是 1.5，
注释说「实测进入录音态约 9」。但微信 4.x 下实测只有 **0.33—0.56**，
于是每次都被判成「没进入录音态」而中止——语音条全军覆没，只会退化去发文件。
已改为 **0.15**（静止画面通常 <0.05，仍能挡住误点）。

**bug 2：失败分支不点取消。** 中止时只存截图、直接 return，**微信被留在录音态**；
下一次调用点「语音按钮」等于「结束录音」，差异更小，越修越坏。已在失败分支补一次
取消点击。

两个改动都在 `src/voice_sender.py`，不只服务点歌，`/语音` 那类命令同样受益。

### 9.4 前置条件：微信窗口必须在前台

`SendInput` 是真实鼠标点击，打给**前台窗口**。微信被压在其他窗口下面时，
点击会落到别的程序上：日志会显示「已进入录音态 / 已发送」，但**数据库里没有**，
属于假成功。试运行里复现了两次。

抢前台用这套（`SetForegroundWindow` 单独调用会被 Windows 挡住）：

```powershell
# 先模拟一次 Alt 按键解除前台锁，再 SetForegroundWindow
[FG]::keybd_event(0x12, 0, 0, [UIntPtr]::Zero)
Start-Sleep -Milliseconds 80
[FG]::keybd_event(0x12, 0, 2, [UIntPtr]::Zero)
[FG]::ShowWindow($h, 9) | Out-Null
[FG]::BringWindowToTop($h) | Out-Null
[FG]::SetForegroundWindow($h) | Out-Null
```

发完一定要**回读数据库确认**（`_check_group.py`），不要只信日志。

```

{ "text": "唱一段 兰亭坤序", "platform": "wechat",
```

## 十、曲库补歌与「别名」（2026-10-18 10:00 补）

### 10.1 加一首歌只要两步

1. 把音频丢进 `曲库\`，命名 `歌手 - 歌名.wav|ogg|mp3`（不带歌手也行，只是显示「未知歌手」）。
2. 重启 bot（曲库在启动时扫进内存）。

B 站来源可以用 `_grab_song.py` 直接抓：

```bat
python _grab_song.py BV1VU4y1D7Ny "兰亭鸡序"
```

（复用 `cover.py` 的 `platform=html5` 直链口子，不需要 yt-dlp。）

### 10.2 同一个歌有多个叫法 → `原名.json`

梗歌经常一堆名字。曲库目录下放 `别名.json`：

```json
{
  "兰亭鸡序": ["兰亭坤序", "坤亭序", "兰亭鸡序2.0", "鸡你太美"]
}
```

- 键是**曲库里的文件名（不含扩展名）**，值是其它叫法。
- 实测：`兰亭鸡序 / 兰亭坤序 / 坤亭序` 三个说法都命中同一首；
  `兰亭序` 因为模糊匹配相似度 0.86 也会命中（介意的话把 cutoff 调高）。
- 启动日志会出现 `[点歌] 从 别名.json 挂了 N 个别名`。
